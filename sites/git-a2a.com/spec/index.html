Specification overview

# a2amodule specification, schema 1

An `a2amodule.yml` file describes a git repository—or one module directory in a
monorepo—as reusable code with explicit agent ownership. The adjacent
`a2amodule.lock` records the exact revision seen by a consumer. Local fetched data lives
under `.git-a2a/` and is never committed.

The normative source is [`_.hint`](./_.hint); see
[Specification as source (HINT)](../README.md#specification-as-source-hint) for how HINT exposes
the knowledge governing a path. The JSON Schemas in [`schema/`](./schema/)
are the machine-readable form and are published at
[`/schema/a2amodule.v1.json`](https://git-a2a.com/schema/a2amodule.v1.json) and
[`/schema/a2amodule-lock.v1.json`](https://git-a2a.com/schema/a2amodule-lock.v1.json).
Complete manifests live in [`examples/`](./examples/).

Use the generated [manifest field reference](../docs/manifest-reference.md) for every field's
type, default, allowed values, behavior, and consequence. The [authoring guide](../docs/authoring.md)
walks from an empty repository to a published module using the public demo. Consumers follow the
[consumer guide](../docs/consuming.md); contact transport fields and behavior are generated in
[contact kinds](../docs/contact-kinds.md), and design boundaries are answered in the
[FAQ](../docs/faq.md). Exact executable behavior is in the [CLI reference](../docs/cli.md).
Agent and operator integration is collected in [For agents](../docs/agents.md).

## Manifest

Top-level keys use this canonical order: `schema`, `module`, `agents`, `policy`, `settings`,
`dependencies`, then extension keys. `schema` is `1`. `module.id` is the only other
required field.

- `module` names and describes the module, its published `surface`, release channel,
  canonical `repository`, optional `moved-to` handoff, languages, documentation, and ecosystem
  exports. `repository` identifies the owner-declared source but is not fetched implicitly;
  `moved-to` is reported and followed only after explicit `update --follow-moves` or `set`.
  Ecosystem values use package-url type names but remain an open vocabulary.
- `agents` binds existing agents to roles and path scopes. A binding points to an A2A
  card; it does not duplicate the card's self-description. Ordered contacts say how the
  agent accepts each request intent.
- `policy.intents` maps an intent to a role. Consumer permissions are declared under
  `policy.consumers.may` and `may-not`; optional `policy.contact-budget` publishes sorted,
  open-vocabulary usage expectations without enforcing them.
- `dependencies` identifies other modules by git URL, ref, optional monorepo `path`, tracking
  mode, and optional ecosystems to wire. An absent `wire` means every detected applicable
  ecosystem; `wire: []` means none; a non-empty list makes exactly those adapters mandatory.
  Ecosystems that cannot express a source report `not wired` under implicit policy and fail the
  transaction when explicitly required.

Unknown vocabulary values—roles, intents, contact kinds, and ecosystems—are valid.
Unknown object keys are invalid unless they start with `x-`.

## Schema evolution

Schema 1 evolves additively: new fields are optional and existing valid documents retain their
meaning. Removing or renaming a field, making it required, closing an open vocabulary, changing a
default, or changing a committed value's type/meaning requires schema 2, a `git-a2a migrate`
command, and a documented deprecation window. A tool refuses a newer schema instead of guessing.
`git-a2a validate --schema-report` lists the optional schema paths a document actually uses so a
second implementation can state its coverage precisely.

## Vendored dependencies

Vendoring is an explicit consumer choice under `dependencies[].vendor`; it never changes the
owner module. `mode: submodule` (the CLI default when `--vendor` is requested) records a Git
submodule at the locked commit, while `mode: copy` records and verifies a deterministic tree
copy. `path` defaults to `settings.vendor-dir` plus the dependency id (`deps/<id>` by default),
and `recursive` controls nested submodules. The lock records the realised mode, path, commit,
and tree identity; dirty or drifted materialisation is unhealthy and is never overwritten or
removed without explicit `--force`.

Integration-only build systems consume the local tree through generated CMake, Gradle, MSBuild,
Maven, or Meson wiring. Native ecosystems use their local path form—npm `file:`, Cargo `path`,
Go `replace`, uv/Pub/Mix `path`, and Composer `type: path`—instead of a Git selector. Meson
requires an explicit `vendor.path: subprojects/<id>` because Meson rejects traversal in wrap
directories. `fetch` restores the exact vendored state from the lock after clone; `status`
shows `VENDOR` only when at least one dependency declares it.

## Consumer lifecycle

`add` resolves a dependency and writes one lock commit for every ecosystem. `fetch` reconstructs
the ignored `.git-a2a/cache` from that lock after a fresh clone. `sync` projects only published
module, surface, policy, ownership, and contact data into a bounded AGENTS.md block. `status`
checks the locked cache, native wiring, upstream movement, cards/trust, and roster; `update`,
`set`, `pin`, `unpin`, and `wire` change the dependency deliberately and transactionally.
`who` resolves an owner route and `contact` chooses a consumer PATH plugin, built-in A2A/forge
driver, consent-gated declared invocation, or exact instruction—in that order. GitLab and
Gitea/Forgejo/Codeberg repositories use the same core lifecycle as GitHub or a bare Git server;
only issue delivery differs. The [contact-kind reference](../docs/contact-kinds.md) and
[plugin protocol](../docs/contact-plugins.md) define that boundary. The
[consumer guide](../docs/consuming.md) gives the complete sequence
and the non-mutating CI pattern.

## Routing

Routing is deterministic: request intent → role from `policy.intents` (default
`owner`) → the most specifically scoped matching agent → matching contacts in declared
order. An exact intent is preferred to the `"*"` fallback. The CLI reports the declared
contacts; it does not choose a fleet or communication platform.

For example, with `policy.intents.change: spec`, a request for `change` under `api/**` first
selects agents whose role is `spec`, then prefers an `api/**` scope over `**`, and finally emits
that agent's `change` contacts in manifest order. If no exact contact accepts `change`, a
contact whose intents contain `"*"` is the fallback.

## Lock and local state

The lock is CLI-owned deterministic YAML. Each dependency entry records `git`, `ref`, `path`,
one resolved 40-hex `commit`, `manifest: sha256:<hex>`, optional `cards` hashes, and—when
materialised—`surface: tree:<40-hex>`. Every ecosystem adapter pins the same commit. There are
no timestamps or machine paths.

`.git-a2a/cache/<id>/` contains the fetched manifest, card snapshots, optional published
surface, fetch metadata, and an implementation working area. It is disposable and must
be ignored by git.

## A2A projection

Agent cards remain native A2A v1.0. `git-a2a card export` starts from a snapshotted card
or synthesises a minimal card from an A2A contact, then adds the stable extension
`https://git-a2a.com/ext/module/v1`. Its params bind the card to the module, repository,
role, scope, and ref. Skills and other native card fields are left untouched.

`agents[].trust.signatures: true` requires at least one valid JWS signature over the RFC 8785
canonical card, bound to pinned `jwks`/`keys` or a reported same-origin fallback. Origins,
key-cache age, key rotation, consumer-required signed cards/commits, and external-contact policy
are defined in the generated reference and explained in the [trust guide](../docs/trust.md).
An unsigned, invalid, revoked, or unexpectedly re-keyed card makes `status` unhealthy;
`git-a2a card verify FILE|URL [--jwks URL] [--key THUMBPRINT]` exercises the same verifier.

`git-a2a catalog export [--out ai-catalog.json]` emits an ARD 1.0 catalog. Public card URLs stay
references; repository-relative or synthesised cards are embedded as
`application/a2a-agent-card+json`. The catalog indexes cards and never becomes another agent
description.

## Canonical YAML

CLI-owned YAML uses two-space indentation, the key order described above, block scalars
for multiline descriptions and notes, and block collections. A short contact may use a
flow map. Maps whose ordering is semantic (notably lock dependencies and card hashes)
are sorted lexicographically. Files end with one newline and contain no timestamps or
absolute machine paths.

Normal commands preserve a hand-written manifest's comments and key order outside the
precisely addressed entry they change. `git-a2a fmt` is the explicit request to rewrite
the whole manifest canonically.

See the [library](./examples/acme-lib-utils.a2amodule.yml),
[consumer](./examples/acme-app-cli.a2amodule.yml), and
[monorepo](./examples/acme-monorepo-consumer.a2amodule.yml) examples. Vendored build-system
examples cover [CMake](./examples/acme-cmake-consumer.a2amodule.yml) and
[Gradle](./examples/acme-gradle-consumer.a2amodule.yml).

# app The a2amodule standard

This folder is the normative description of `a2amodule.yml` (also accepted as
`a2amodule.yaml`), `a2amodule.lock`, the local state
directory `.git-a2a/`, and the A2A card projection. It is written for two readers: an agent or
human authoring a manifest for their repository, and the implementer of any tool that consumes
one (the reference CLI lives in `cmd/`, but nothing here depends on it). `spec/examples/` holds
complete manifests for the two pilot repositories and must always validate.

Formats: YAML 1.2 for the manifest and lock (JSON is valid YAML, so a JSON manifest is
accepted). Keys are lower-case kebab-case. Relative paths are POSIX, relative to the directory
that contains the manifest. JSON Schemas for the manifest (`spec/schema/a2amodule.schema.json`,
public id `https://git-a2a.com/schema/a2amodule.v1.json`) and lock
(`spec/schema/a2amodule.lock.schema.json`, public id
`https://git-a2a.com/schema/a2amodule-lock.v1.json`) are emitted from this spec; the manifest
schema is what `git-a2a validate` enforces.

# term module

The unit of ownership and import: a git repository, or a subdirectory of one, that carries an
`a2amodule.yml` or `a2amodule.yaml`. Repository is the default unit, following git's own
boundary; a subdirectory module exists for monorepos and is addressed by consumers with `path:`.

# term surface

The directory the owner publishes for consumers: API summaries, usage, limits, examples. It is
the only content of the dependency a consumer may read besides the manifest itself. Its location
is declared (`module.surface`); there is no hard-coded path.

# term vendored dependency

A dependency whose source tree is checked out inside the consumer's repository — as a git
submodule (a gitlink pinned to the locked commit) or as a plain copy — instead of, or in
addition to, a package-manager reference. It serves toolchains that have no native Git dependency
form and permits deliberate source-level integration for toolchains that do. The consumer decides;
the dependency publishes exports but cannot make a consumer vendor them.

# term intent

What a request is for. Core tokens: `question`, `change`, `bug`, `review`, `incident`. The set is
open; `"*"` in a contact means "any intent not matched more specifically".

# term role

What an agent does for this module. Core tokens: `owner` (commits, merges, releases),
`maintainer` (commits under review), `spec` (owns specifications, tasks, sequencing; writes no
product code), `reviewer`, `support`. The set is open.

# entity a2amodule.yml or a2amodule.yaml {#manifest}

The canonical filename is `a2amodule.yml`; `.yaml` is an accepted alternate. Readers probe
`.yml` before `.yaml`, generators write `.yml`, and a directory containing both is invalid
because a module has exactly one manifest. Fetched caches retain the upstream filename.

Top-level keys, in canonical order: `schema`, `module`, `agents`, `policy`, `settings`,
`dependencies`. `schema`, `module` and `module.id` are required; everything else is optional.
Unknown keys are errors except `x-*`.

## field schema

integer; the format version of this file. Value `1` for this specification. A consumer that
sees a larger value than it knows must refuse the file (exit 2), not guess, with
`schema <value> is newer than this tool supports (1); upgrade git-a2a`. A smaller or otherwise
invalid value is an ordinary validation failure (exit 1).

## field module

object; the module description. See [#module](#module).

## field agents

list of agent bindings, see [#agent](#agent). Empty or absent means "no agent owns this; treat
as a plain library" — still importable, nobody to ask.

## field policy

object, see [#policy](#policy). Routing defaults and consumer permissions.

## field settings

object, see [#settings](#settings). Consumer-local defaults; owners of dependencies never read
these settings from a consumer.

## field dependencies

list, see [#dependency](#dependency). Modules this module depends on.

# entity settings {#settings}

Consumer-local behavior for this repository. Unknown keys are errors except `x-*`.

## field vendor-dir

string, optional relative path, default `deps`. Parent directory used when a vendored dependency
does not declare `vendor.path`. `vendor/` is deliberately not the default because Go and Composer
assign their own semantics to that name. Changing it moves only dependencies that use the default;
explicit `vendor.path` values remain unchanged. It obeys all vendored-path safety rules.

## field sync-targets

list of relative paths, optional. Additional files whose managed roster block `sync` maintains.
Changing the list changes sync destinations, not dependency resolution or vendoring.

## field organisation

list of strings, optional. Origins or `origin/owner` prefixes that count as "our organisation"
for `accepts-external` decisions, e.g. `["https://github.com/neprel", "ssh://git.internal"]`.
Default: the origin host and first path segment of `module.repository`. Changing it changes only
the external-contact boundary used by `contact`.

## field contact

object, optional: consumer consent for owner-described invocations. `allow-http` — list of
origins (`https://host[:port]`); a dependency's `http` contact is delivered only when its URL's
origin is listed, otherwise it renders as an instruction. `allow-exec` — list of bare binary
names; a dependency's `exec` contact runs only when `command[0]` is listed and resolves on
PATH. The lists live in the consumer's own manifest, so consent is authored, reviewed, and
versioned by the consumer — never by the dependency. Defaults: empty, meaning instruction-only.

## field x-*

extension keys, preserved.

# entity module {#module}

## field id

string, required. Stable identifier, `^[a-z0-9][a-z0-9._-]{0,63}$`. Consumers refer to the
dependency by this id and the lock keys on it; `add` verifies that the fetched manifest's `id`
equals the id the consumer expected (when given) and otherwise adopts it. Renaming an id is a
breaking change for every consumer.

## field name

string. Display name. Defaults to `id`.

## field description

string, recommended. One paragraph answering "what is this and what is it for" — it is what a
consumer's agent reads in its roster, so it should also say what kind of questions the owner
expects. Whitespace is normalised when rendered.

## field languages

list of strings, open vocabulary and informative. Known tokens and their behavior are in
`vocabulary_languages`. Not used for wiring; `exports` is. Changing it changes discovery metadata
only; unknown values are accepted and preserved.

## field surface

string; relative directory path. Published content for consumers. Absent means nothing is
published beyond the manifest.

## field repository

string; the canonical git URL of this module as its owner declares it. Lets a consumer that
obtained the module from elsewhere (a fork, a mirror, a copy) see that it is not on the
canonical source — and that the `agents` listed may belong to the original owner rather than
to whoever maintains the copy. Informative; never used to fetch.

## field moved-to

object, optional: `git` (string, required; the new canonical URL), `path` (string), `notes`
(string). An owner leaves it in the last manifest at the old location when the module moves.
Consumers are told on `update` and follow it only on explicit request; a tool never switches a
source silently.

## field docs

string; URL of human documentation.

## field release

object: `channel` (string, the ref consumers should follow by default, e.g. `main`), `tags`
(boolean, whether semver tags are published), `notes` (string, free text, e.g. "main is the only
release channel"). `release.channel` is the default `ref` a consumer gets when it adds this
module without naming one.

## field exports

list of export entries; how to import this module per ecosystem. Each entry: `ecosystem`
(string, required; use package-url type names: `npm`, `pypi`, `golang`, `cargo`, `maven`,
`nuget`, `swift`, `cocoapods`, `pub`, `gem`, `composer`, `hex`, `hackage`, …), `name` (string,
required; the name the ecosystem imports: npm package name, PEP 503 distribution name, Go module
path, crate name, Maven `group:artifact`), `path` (string, optional; subdirectory containing the
ecosystem's own manifest, default the module directory), `notes` (string, optional; anything a
wiring tool or agent must know, e.g. "vanity import path, needs replace", "prepare script builds
dist"). Ecosystem-specific keys are allowed under `x-<ecosystem>-*`.

# entity moved-to {#moved_to}

The relocation notice stored at `module.moved-to`. It announces a destination but never grants
the tool permission to rewrite consumer sources automatically.

## field git

string, required. New canonical Git URL. Changing it changes the destination offered to users;
consumers remain on the current source until an explicit `set --git`.

## field path

string, optional relative path, default `.`. Subdirectory containing the moved module. Changing
it changes the destination module root offered with the new Git URL.

## field notes

string, optional. Human migration context printed with the move notice. Changing it changes only
the guidance, never the source automatically.

# entity release {#release}

The owner's default Git release policy under `module.release`.

## field channel

string, optional. Default ref used by `add` when the consumer supplies no ref, commonly `main`.
Changing it affects future adds; existing consumers retain their declared ref until `set`.

## field tags

boolean, optional, default `false`. Declares whether the owner publishes semantic-version tags.
Changing it changes what consumers may reasonably select with `set --ref`; it does not create tags.

## field notes

string, optional. Free release-channel guidance shown to consumers. Changing it changes guidance
only and does not resolve or move a dependency.

# entity export {#export}

One importable ecosystem representation in `module.exports`.

## field ecosystem

string, required, open vocabulary. Known values and adapter behavior are in
`vocabulary_ecosystems`. Changing it selects a different adapter and therefore a different native
manifest; an unknown value remains valid published metadata but has no wiring adapter.

## field name

string, required. Native package/import name in the named ecosystem. Changing it rewires the
consumer from the old native entry to the new one on the next mutation or `wire`.

## field path

string, optional relative path, default `.`. Subdirectory containing the ecosystem package.
Changing it changes the Git subdirectory expression; unsupported adapters report `not wired`.

## field notes

string, optional. Export-specific facts shown to tools and agents. Changing it changes published
guidance but does not itself alter adapter behavior.

# entity agent binding {#agent}

One entry in `agents`. Binds an existing agent to this module; does not define the agent.

## field name

string, required. The agent's own name — must equal `name` in its A2A card when a card is given.
An agent may appear in many modules (one agent, many repositories) and a module may list many
agents (one repository, many agents), so `name` must be stable across repositories. Identity
for de-duplication across modules is the `card` URL when present, else `name`; two bindings in
different modules with the same card URL are the same agent, and tools may merge what they know
about it. Names are scoped to whoever controls the card URL, so a public ecosystem never relies
on a bare name being globally unique.

## field role

string, required, open vocabulary. A role says what the agent owns for this module; core values
and routing consequences are in `vocabulary_roles`. Unknown roles are accepted and participate in
routing when `policy.intents` names the same token.

## field scope

list of glob patterns relative to the module directory. What this agent answers for and may
change. Default `["**"]`. Two agents may overlap; resolution prefers the more specific match,
then declared order.

## field card

string. URL of the agent's A2A Agent Card (`https://…/.well-known/agent-card.json`) or a
repository-relative path to a card file (A2A "direct configuration"). When present the card is
the authority for `description`, `skills`, interfaces and security; git-a2a snapshots it.

## field description

string. Only when no card is available or to add module-specific wording ("for this repository,
ask it about …"). Never a copy of the card's description.

## field contacts

ordered list. Each contact: `intents` (list of strings, required; `"*"` allowed), `kind`
(string, required; open vocabulary, see [#contact_kinds](#contact_kinds)), `note` (string,
optional; free-text instructions shown verbatim to the asker, e.g. "state the version you are
on"), plus kind-specific keys. Order expresses preference within an intent.

## field trust

object, optional: `signatures` (boolean), `accepts-external` (boolean), `jwks` (list of https
URLs), `keys` (list of JWK SHA-256 thumbprints, RFC 7638), `origins` (list of origins
`scheme://host[:port]`), `jwks-max-age` (duration, default `24h`), `x-*`. Defaults: no
verification required, external not stated, nothing pinned.

Verification when `signatures: true`: at least one detached JWS over the RFC 8785 canonical card
(top-level `signatures` excluded) must verify with a key that is (a) in a JWKS whose URL is listed
in `jwks`, or (b) whose thumbprint is listed in `keys`, or — only when both lists are empty — (c)
served by a `jku` with the same origin as the card URL, in which case `validate` and `doctor`
report "unpinned key source". The first verified `kid` and thumbprint are recorded in the lock
(`cards-keys`); a different key later is a `status` failure `trust: key changed` until the
consumer accepts it with `update --accept-keys`. Keys missing from a freshly fetched JWKS no
longer verify. An unsigned, invalid or unverifiable card makes `status` fail; `update` retains
the dependency update but prints a trust warning.

Origin check (always on, severity depends on `signatures`): the card URL and every
`supportedInterfaces[].url` must be in `origins` when declared; otherwise their origin must equal
the origin of `module.repository`, or the card's git-a2a extension `params.repository` must equal
the dependency's canonical `git`. A mismatch is a failure when `signatures: true` or when the
consumer requires `card-origin`, a warning otherwise.

# entity contact {#contact}

One ordered delivery or instruction route in `agents[].contacts`. `intents` and `kind` are common;
the remaining keys are valid only for the kinds listed in [#contact_kinds](#contact_kinds).

## field intents

list of strings, required and non-empty, open vocabulary; `"*"` is the fallback. Changing the
list changes which requests may select this contact. Core values, fallback behavior, and unknown
handling are in `vocabulary_intents`.

## field kind

string, required, open vocabulary. Changing it selects another delivery driver or instruction
renderer and changes which kind-specific fields are valid. Known values and unknown handling are
in `contact_kinds`.

## field note

string, optional. Instructions printed verbatim after the route. Changing it changes the asker's
guidance, not routing priority or delivery mechanics.

## field url

string, optional for `a2a`, `jira`, and `url`, required and HTTPS for `http`. Changing it changes
the service or instruction destination; for A2A it is the JSON-RPC endpoint. `http` templates may
place non-message placeholders only in query values according to `contact_placeholders`.

## field skill

string, optional for `a2a`. Skill identifier requested from the remote agent. Changing it changes
the A2A target skill without changing the endpoint.

## field address

string, optional for `email`. Destination email address. Changing it changes the recipient.
The reference CLI pipes RFC 5322 mail to consumer-installed `sendmail`, otherwise uses consumer
SMTP configuration, otherwise prints the instruction.

## field subject-prefix

string, optional for `email`. Prefix suggested for the email subject. Changing it changes only
the printed instruction.

## field repo

string for `github-issue`, `gitlab-issue`, `gitea-issue`, and `bitbucket-issue`; normally
`owner/name`, while GitLab permits nested `group/subgroup/name`. Changing it changes the repository
where the issue driver delivers the request.

## field labels

list of strings, optional for issue kinds. Changing it changes labels requested when an issue is
created; a missing label is a delivery error from the host.

## field template

string, optional for issue kinds. Issue form/template name. Changing it changes the requested
template without changing routing.

## field organization

string for `azure-boards`. Changing it changes the Azure DevOps organization named by the
instruction.

## field method

string, optional for `http`, default `POST`. Changing it changes the exact instructed or allowed
HTTP request method.

## field headers

map of string to string, optional for `http`. Values are static literals: placeholders are invalid,
and git-a2a never adds credentials from the declaration or consumer environment.

## field content-type

string, optional for `http`. It selects the request Content-Type and JSON-aware placeholder
escaping when it contains `json`.

## field body

string template, optional for `http`. It may use every value in `contact_placeholders`, including
`{message}`; changing it changes the exact instructed or delivered payload.

## field command

list of strings, required for `exec`. The first item is a bare binary name without a path separator;
remaining items are argv entries. It is never interpreted by a shell.

## field args

list of string templates, optional for `exec`, appended to `command`. It may use every non-message
placeholder in `contact_placeholders`; changing it changes argv only.

## field stdin

string template, optional for `exec`, default `{message}`. It may use the complete placeholder set
and is passed as stdin without shell or environment expansion.

## field project

string for `jira` and `azure-boards`. Project key. Changing it changes the project named in the
instruction.

## field issue-type

string, optional for `jira`. Issue type. Changing it changes the Jira issue kind named in the
instruction.

## field channel

string, optional for chat kinds. Channel name or id. Changing it changes the printed chat
destination; chat contacts are instruction-only.

## field handle

string, optional for chat kinds. Agent mention or handle. Changing it changes whom the asker is
told to address.

## field server

string, optional for chat kinds. Workspace or server URL/name. Changing it disambiguates the
printed chat destination.

# entity trust {#trust}

Verification and request-origin expectations for one agent binding.

## field signatures

boolean, optional, default `false`. When changed to `true`, unsigned, invalid, or unverifiable
cards make `status` fail and make `update` warn while retaining the dependency update.

## field accepts-external

boolean, optional, default unstated. `false` is enforced by `contact`: a consumer whose
organisation differs from the owner's is refused (exit 2) unless `--external-ok`; `who` marks the
agent "(external requests not accepted)". Organisation = origin host plus first path segment of
`module.repository`, or the values of `settings.organisation` when declared.

## field jwks

list of HTTPS URLs, optional. A card signature may use a key served by one of these pinned JWKS
sources. Changing the list changes the accepted key authorities; a newly selected key is still
subject to lock key-change review.

## field keys

list of RFC 7638 JWK SHA-256 thumbprints, optional. A card signature may use a key matching one
of these pins regardless of JWKS URL. Changing the list changes the exact accepted public keys.

## field origins

list of `scheme://host[:port]` origins, optional. When present, card and interface URLs must use
one of these origins. Changing it changes the allowed network identity of the agent binding.

## field jwks-max-age

duration string, optional, default `24h`. Online status refreshes older JWKS cache entries;
offline status reports their age. Changing it changes refresh freshness, never the cache's
recoverable status.

# decision ARD catalogs index native Agent Cards

`git-a2a catalog export` projects the module's agents into an ARD 1.0 `ai-catalog.json`.
Each entry uses `application/a2a-agent-card+json` and exactly one of `url` or `data`: public
card URLs stay references, while repository-relative and synthesized cards are embedded.
Identifiers are deterministic domain-anchored `urn:air` values derived from the module
repository and agent name. The catalog never becomes a second description of an agent.

Issue-kind instructions include a prefilled, URL-encoded and length-capped deep link when the
forge supports one, so a driverless contact is one click for a human and one request for an
agent. GitHub, Gitea, and Bitbucket use `…/issues/new?title=…&body=…`; GitLab uses
`…/-/issues/new?issue[title]=…&issue[description]=…`. The title is the same capped first
non-empty message line used by delivery drivers, and the body/description is the capped full
message. Forges without a tracker (Gerrit, Bitbucket Data Center, bare git hosting) are served
by `email`, `jira`, `url`, or a chat kind — contacts bind to intents, not to where the code is
hosted.

Driver resolution per contact, in order: a consumer-installed plugin executable
`git-a2a-contact-<kind>` on PATH; the built-in driver; a declared `http`/`exec` invocation the
consumer has consented to; the rendered instruction. The chosen path is named in the delivery
record and by `contact --list-drivers`.

# data Declared-invocation placeholders {#contact_placeholders}

Templates in `http.url` query values, `http.body`, `exec.args`, and `exec.stdin` may use exactly
`{intent}`, `{module}`, `{origin}`, and — in `http.body` and `exec.stdin` only — `{message}`.
Only an unescaped sequence matching `{[a-z]+}` is recognized as a placeholder: a known name is
substituted, an unknown lowercase name is a validation error, and every other brace sequence is
literal. Double braces `{{` and `}}` encode literal braces when literal `{word}` text is needed.
Thus a JSON object such as `{"module":"{module}"}` is valid without escaping its structural
braces. Each placeholder is escaped for its context: URL query encoding in `url`, JSON string
encoding inside a JSON body, verbatim in a plain-text body or stdin. A placeholder anywhere in
`http.headers`, `{message}` outside body/stdin, a non-https `http.url`, or a path separator in
`exec.command[0]` is a validation error.

# entity policy {#policy}

## field intents

map intent → role. Which role answers which intent by default. Absent intents default to
`owner`. Example: `change: spec` sends change requests to the specification agent rather than
the coder — the pattern where engineers have full autonomy inside their repository and none
outside it, and the manager owns the WHAT.

## field consumers

object: `may` and `may-not`, lists of tokens from an open vocabulary (`read-surface`, `ask`,
`open-issue`, `propose-change`, `commit`, `edit-spec`, `release`, …). Rendered verbatim into the
consumer's roster block so an agent sees the boundary before it acts. Defaults when absent:
`may: [read-surface, ask]`, `may-not: [commit]`.

## field contact-budget

map of non-empty string keys to non-empty string values, optional and open vocabulary. It
publishes owner expectations such as `per-consumer-daily: "2"` or a `note`; `who` and the roster
render the entries in sorted order. The reference CLI does not count or enforce them. Changing a
value changes guidance to consumers, not routing or delivery permission.

## field notes

string. Anything else consumers must know, verbatim.

# entity consumers {#consumers}

The open-vocabulary consumer boundary under `policy.consumers`.

## field may

list of strings, optional, default `[read-surface, ask]`. Changing it changes the allowed actions
rendered into consumer AGENTS.md rosters; the CLI reports the boundary but does not become an
authorization service. Known values and unknown handling are in `vocabulary_consumers`.

## field may-not

list of strings, optional, default `[commit]`. Changing it changes the prohibited actions rendered
into consumer rosters; downstream agents remain responsible for obeying the declaration. Known
values and unknown handling are in `vocabulary_consumers`.

# decision Init interviewing is one deterministic authoring contract {#init_interview}

The ordered interview contains, for every question, a manifest field path, prompt, one-line reason,
computed default, confidence (`low` or `high`), and validation rule. Defaults come only from the
same repository state: directory identity, origin URL, detected package manifests, and existing
agent-guidance filenames. `module.id` and `module.description` are always low-confidence; detected
exports are high-confidence. Human TTY answers and a JSON/YAML `--answers FILE|-` field-path map
feed the same manifest renderer. Missing keys accept defaults; unknown keys exit 2 in sorted order.
Therefore identical repository state plus identical answers produces byte-identical output.
`--interview [--json]` only reports this contract and never writes. `--example lib|app` may provide
the baseline before answers override fields; generators continue to write canonical `.yml`.

# entity dependency {#dependency}

One entry in `dependencies`.

A repository without either manifest filename is a **plain git dependency**. `add` derives its
id from the repository name, warns once, and locks its commit with `manifest: none`. Git-only
operations remain available and no command treats the absent manifest as a broken cache.

| Command | Plain-dependency behavior | Exit |
| --- | --- | --- |
| `fetch` | Restores no manifest or surface, says so; restores requested vendoring. | 0 |
| `status` | Shows `MANIFEST plain`, `AGENTS —`, checks upstream and vendoring/wiring. | Normal status semantics. |
| `show` | Prints `plain git dependency; no surface declared`; `--surface` returns that reason. | 0; `--surface` 2. |
| `who`, `contact` | Prints `no agents declared: <id> is not an a2a module`. | 2 |
| `sync` | Renders the dependency as `(plain git dependency)` without an upstream policy quote. | 0 |
| `update`, `set`, `pin`, `unpin`, `remove`, vendoring | Operates on the resolved Git source normally. | Normal mutation semantics. |
| `wire` | Applies vendoring; without a shim reports no exports, while `shim.exports` wire exactly like upstream exports. | 0 |
| dependency card/catalog projection | Skips the dependency with a note. | 0 |

A consumer may attach `shim` metadata to a plain dependency. `shim.exports` has the same shape
and wiring semantics as `module.exports`; optional `shim.agents` uses the normal agent/contact
shape for `who` and `contact`; optional `shim.notes` records local adoption context. Shim content
is authored by and trusted as part of the consumer repository. The generated roster labels it
exactly as “described by this repository's shim, not by the dependency”. A shim applies only while
the locked commit has `manifest: none`. Once an update finds an upstream manifest, every command
uses upstream metadata and reports `shim ignored: upstream declares its own manifest`; the shim is
kept in the consumer manifest so a later plain commit remains deterministic.
Adding or changing `shim.exports` after `add` takes effect on the next bare `wire [ID]`; the CLI
may report `wiring is current` only after the selected shim exports are present in detected
ecosystem manifests.

## field shim

object, optional, see [#shim](#shim). Consumer-authored fallback metadata for a plain Git
dependency.

## field id

string. The dependency's `module.id` for an a2a module, or the repository basename for a plain
dependency. Required after `add` (the CLI fills it); the lock is keyed on it.

## field git

string, required. The git URL (`ssh://`, `https://`, `git@host:path` scp form, `file://`).
Stored exactly as given; credentials are never stored.

## field ref

string. Branch, tag or commit to follow. Default: the dependency's `release.channel`, else the
remote HEAD. Resolution: a 40-hex string is a commit; a full refname (`refs/heads/x`,
`refs/tags/x`) is exactly that; a short name is resolved in git's own order — `refs/tags/<ref>`
before `refs/heads/<ref>` — and an ambiguity is reported with the name chosen. A commit ref
implies `track: locked`. Changing `ref`, `git` or `path` of an existing dependency is an
ordinary edit (`git-a2a set`): identity is `module.id`, so the fetched manifest must carry the
same id unless the consumer explicitly accepts a different one; every wired ecosystem follows
the new source and pin together.

## field path

string. Subdirectory containing the dependency's `a2amodule.yml` or `a2amodule.yaml`
(monorepo), or the adopted plain source root. Default `.`.

## field track

`locked` (default) or `floating`, a closed vocabulary described in `vocabulary_track`. Every mode
still records one observed commit in the lock. Changing the mode rewrites supported native
dependency forms; unknown values are rejected.

## field wire

list of ecosystems to wire, or absent for "every export that matches a manifest detected in this
repository". An empty list means "record the dependency, wire nothing". When `wire` is absent
and an export cannot be expressed in its ecosystem (the ecosystem has no git form for that URL,
no subdirectory support, a floating ref it cannot store), the tool wires what it can, reports
the rest as `not wired: <reason>` and `status` shows that ecosystem as `unwired`; it is an error
only for an ecosystem named explicitly in `wire`. Wiring is repairable at any time
(`git-a2a wire [ID]` re-applies every adapter from the lock, idempotently) — a half-wired
dependency is a state the tool can always see and always fix, never one it hides.

## field vendor

object, optional, see [#vendor](#vendor). Its presence explicitly asks the tool to materialise
the locked source tree in this consumer; a dependency is never vendored implicitly.

## field require

object, optional, see [#require](#require). It states consumer-side checks that must pass before
locking or contacting this dependency. Defaults preserve the permissive behavior.

## field x-*

extension keys, preserved.

# entity consumer shim {#shim}

Trusted fallback metadata written by the consumer for a plain Git dependency. Unknown keys follow
the normal `x-` extension rule.

## field exports

list of `export`, optional. Wired exactly like the dependency's own `module.exports` while the lock
has `manifest: none`.

## field agents

list of `agent`, optional. Routed by `who` and `contact` while the lock has `manifest: none`.

## field notes

string, optional. Trusted local context rendered in the consumer roster with explicit shim origin.

## field x-*

extension keys, preserved.

# entity dependency requirements {#require}

What this consumer insists on before it locks or contacts one dependency.

## field commits

`any` (default) or `signed`. With `signed`, `add`, `update`, `fetch`, and `set` verify the
resolved commit or tag with Git against `signers` before changing the lock. Changing it re-runs
the check on the next mutation and on `status`; unknown values are rejected.

## field signers

repository-relative path to a Git `allowed_signers` file, required when `commits: signed`.
Changing it changes the trusted SSH/GPG signer set. A failed check leaves the lock untouched;
`--insecure-skip-signers` is the explicit override and records `verified: skipped`.

## field cards

`any` (default) or `signed`. `signed` treats every agent binding in the dependency as if it
declared `trust.signatures: true`. Changing it changes whether unsigned or unverifiable cards
are accepted; unknown values are rejected.

## field card-origin

boolean, optional, default `false`. When true, a card or interface origin mismatch is a failure
rather than a warning. Changing it changes mismatch severity, not the origin comparison.

## field x-*

extension keys, preserved.

# entity vendor {#vendor}

The consumer's explicit source-materialisation choice for one dependency. Vendoring changes the
consumer repository and CI, so the consumer is the sole authority for this object.

## field mode

`submodule` (default) or `copy`. `submodule` records a Git gitlink at the locked commit and may
initialise nested submodules. `copy` records a plain Git-metadata-free tree. Changing mode replaces
one representation with the other transactionally; unknown values are rejected.

## field path

string, optional relative path. Default `<settings.vendor-dir>/<dependency-id>`, normally
`deps/<id>`. After slash normalisation it must be `..`-free and non-absolute; it must not be
`.git`, `.git-a2a`, or inside either; must not equal or be inside `module.surface`; must not overlap
another dependency's vendor path; and no existing path component may be a symlink. For submodule
mode it must not already be tracked or be a submodule registered with another URL. Validation
reports violations and never silently rewrites the path.

## field recursive

boolean, optional, default `false`. In submodule mode, initialise the dependency's own nested
submodules. In copy mode `true` is invalid because a Git tree contains nested gitlinks, not their
content. Changing it changes only nested-submodule initialisation.

## field x-*

extension keys, preserved.

# entity a2amodule.lock {#lock}

YAML, written only by the CLI. `schema: 1`; `dependencies:` map keyed by dependency id with
`git`, `ref`, `path`, `commit` (40-hex, the resolved ref), `manifest` (`sha256:<hex>` of the
fetched manifest bytes, or exact token `none` for a plain git dependency), `cards` (map agent name → `sha256:<hex>` of the snapshotted
card, present only for agents with a `card`), `cards-keys` (map agent name → `{kid,
thumbprint, jwks, first-seen}` recording the first accepted signature key), `verified` (`signed`
or `skipped`, absent when commit verification was not required), `surface` (`tree:<40-hex>`, the git tree object id of the surface directory at `commit`,
recorded whenever the surface is fetched), and `vendor` for a vendored dependency: `mode`,
resolved `path`, and, for copy mode, `tree` (`tree:<40-hex>` for the copied repository or module
subtree). Checkout strategies obtain surface ids with
`git rev-parse <commit>:<surface>`; the archive strategy derives the same Git tree object id from
the archived entries. Keys sorted; no timestamps, no absolute
paths, no hostnames beyond what the manifest already contains. A lock entry without a
matching manifest dependency is stale and `status` reports it.

`cards-keys` and `verified` are written by `add`, `update`, and `set`, never by `status`. A
different card key is rejected until `update --accept-keys`; `verified: skipped` records the
explicit `--insecure-skip-signers` override rather than implying a successful signature check.

# decision Vendoring is explicit, consumer-decided, and submodule-first {#vendoring}

An owner describes source layout through exports; only a consumer may add `dependencies[].vendor`.
The CLI may recommend `git-a2a set <id> --vendor submodule` when no native Git form exists, but
never adds vendoring implicitly. Submodule is the default mode because its gitlink is already a
content-addressed pin and ordinary clones can opt into `--recurse-submodules`; copy is the explicit
alternative for repositories whose CI or policy rejects submodules. Subtree mode is not planned.

# decision Vendored provenance is the lock and Git object identity {#vendor_provenance}

For submodule mode, `git ls-files -s <vendor.path>` must have mode `160000` and an object id equal
to `lock.commit`; dirty or uninitialised submodules are separate findings. Nested submodules are
fixed by the outer commit and `vendor.recursive` controls only their initialisation. For copy mode,
the lock records the dependency tree id at `commit` (`<commit>^{tree}` for dependency path `.`,
otherwise `<commit>:<dependency.path>`) as `vendor.tree`; drift computes the equivalent tree from
the consumer index entries below `vendor.path`, excluding only the informational
`.git-a2a-vendored` stamp. It does not inspect worktree modes, so Windows `core.fileMode`
differences do not create drift. The stamp contains id, commit, and tree but is not authoritative.

# decision Vendored mutations refuse dirty data and roll back completely {#vendor_transactions}

`update`, `set`, and `remove` refuse a dirty vendored submodule, a submodule commit not contained
in the locked commit, or a copy whose indexed tree differs from the lock. `--force` is the explicit
data-loss override. A failed submodule mutation deinitialises it, removes the cached gitlink,
deletes `.git/modules/<path>`, drops its `.gitmodules` section, restores the original
`.gitmodules` bytes, and restores manifest, lock, wiring, and cache. Copy removal uses `git rm -r`.
No failed transaction leaves a worktree, gitlink, `.gitmodules` entry, or `.git/modules` residue.

# decision Vendor status is explicit without widening ordinary output {#vendor_status}

Machine-readable status always carries a `vendor` state for every dependency. Human status adds
the `VENDOR` column only when at least one dependency in the consumer manifest or lock is
vendored; a consumer using only native Git forms retains the compact table. Once shown, the
column reports `none`, `submodule @<sha7>`, `copy`, `missing`, or `drift` and remains aligned by
the same tabwriter as every other column.

# decision Copy mode preserves Git tree semantics {#vendor_copy_tree}

Copy materialisation preserves regular/executable modes and creates 120000 entries as symlinks.
On Windows without symlink privilege it fails with a clear error instead of converting a symlink
to a regular file. Copy mode never expands nested submodules and rejects `recursive: true`.

# decision Wiring chooses path, native Git, then integration {#vendor_wiring_priority}

For every export the order is: (1) when `vendor` is set and the ecosystem supports a path form,
wire `<vendor.path>/<dependency.path>/<export.path>` (copy mode already starts at the dependency
path, so its export path is relative to `<vendor.path>`); (2) otherwise use its native Git form;
(3) when vendored and an integration adapter exists, wire the generated integration; (4) report
`not wired: <reason>`. Submodule mode always checks out the whole repository; copy mode copies only
the dependency module path. Verbose status names the selected branch, such as `npm path`, `golang
native`, or `maven integration`.

Meson is the one integration with a native directory constraint: its subprojects must be direct
children of `subprojects/`, and Meson rejects path traversal in a wrap `directory`. A Meson
consumer therefore declares `vendor.path: subprojects/<dependency-id>` with no dependency or
export subpath. The adapter rejects other layouts with the corrective `set --vendor-path`
command; it never creates a symlink as an implicit workaround.

# entity .git-a2a/ local state {#cache}

Never committed (`init` appends `.git-a2a/` to `.gitignore`). Layout:
`.git-a2a/cache/<dependency-id>/a2amodule.yml` (the fetched manifest at the locked commit),
`…/cards/<agent-name>.json` (snapshots), `…/surface/` (sparse checkout of the published
surface, fetched on demand), `…/meta.yml` (commit, fetch method). An implementation may keep its working clone under
`…/.src/`. The cache is always reconstructible from `a2amodule.lock`: `git-a2a fetch [ID ...]`
fetches manifests at the locked commits and verifies their byte hashes, while `--surface`
additionally restores surfaces whose tree hashes are recorded in the lock. It does not resolve
moving refs or change the manifest, lock, or adapter files; a missing lock/hash or mismatched
content fails instead of accepting unpinned bytes. Deleting the directory therefore loses no
durable state.

# entity A2A projection {#a2a_projection}

`git-a2a card export <agent>` produces an A2A Agent Card v1.0 JSON document: if the binding has
a `card`, the snapshot is taken as the base; otherwise a minimal card is synthesised from
`name`, `description` (binding, then module) and the `a2a` contact(s) as `supportedInterfaces`
(`protocolBinding: JSONRPC`, `protocolVersion: "1.0"` unless stated). In both cases the
extension `{ uri: "https://git-a2a.com/ext/module/v1", required: false, params: { module,
repository, role, scope, ref } }` is added to `capabilities.extensions` (replacing an existing
entry with the same uri), and `skills` is left untouched. An agent with neither a card nor an
`a2a` contact cannot be exported (exit 2, with the reason) — A2A requires an interface. `card
validate` checks a card file or URL against the v1.0 schema. `catalog export` emits an ARD
`ai-catalog.json` listing the module's agents (see the ARD decision above).

# openquestion Compatibility and breaking changes between module revisions

The standard identifies a dependency revision by commit and tracks a ref; it says nothing yet
about how an owner declares a breaking change or a compatibility range (semver tags exist only
when `release.tags` is true). Candidates: a `module.version` (semver, bumped by the owner),
`release.compat` notes, or leaving it to the ecosystems' own versioning. Decide during the
pilots from observed need; until then `update` always reports the old→new commit and the
manifest diff, and consumers decide.

# decision Schema 1 evolves additively and breaking shapes require migration {#schema_versioning}

Schema `1` may gain only optional fields, optional enum values in vocabularies already declared
open, and clarifications that preserve every previously valid document's meaning. Removing or
renaming a field, making an optional field required, closing an open vocabulary, changing a
default, or changing the meaning/type of a committed value is breaking: it requires schema `2`,
a `git-a2a migrate` command, and a documented deprecation window during which schema 1 remains
readable. A consumer must refuse a schema newer than it implements rather than partially apply it.

`git-a2a validate --schema-report` is the portable coverage report for another implementation.
For every valid manifest or lock it prints the schema number and the sorted set of optional schema
paths that are actually present. Sequence elements use `[]`; required fields are omitted; an
explicit empty collection, empty string, or `false` still counts as present. Human output is one
file followed by feature lines; JSON adds `schema` and `features` to each ordinary validation
record. The report reads only the requested files and remains deterministic.

# invariant Validation never depends on the network

`git-a2a validate` checks structure, vocabularies, path shapes and cross-references inside the
manifest and lock. Reachability of cards, remotes and channels is `status`'s job.

# decision Validation is implemented by typed Go decoding plus explicit structural checks

The reference CLI uses `gopkg.in/yaml.v3` with `KnownFields(true)` and explicit validation
for patterns, relative paths, extension keys and cross-references. It does not load a JSON
Schema engine at runtime. The published JSON Schema remains the portable contract and tests
exercise the same valid and invalid examples through the CLI. This keeps the binary and its
dependency graph small while retaining path-specific diagnostics.
